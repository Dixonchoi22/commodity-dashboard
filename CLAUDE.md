# CLAUDE.md — agent orientation

This repo produces **quarterly commodity intelligence dashboards** as static
HTML under `public/reports/`. Each quarter is built by a small Python
pipeline that turns raw source files (PDF, xlsx, Eurostat / Destatis
exports) into JSON, then renders the JSON into a single HTML file via
`scripts/build_html.py`.

**Front-end.** The site root (`index.html`) is the **redesigned category-first
SPA** — a dependency-light vanilla-JS single-page app (`public/reports/app.html`)
that reads `public/reports/app-data.js` (generated by
`scripts/build_app_data.py` from every quarter's JSON). It renders the quarter
menu, the category-first report (category rail, movers, detail table,
procurement actions, commodity modal), and the Germany deep-dive.
`scripts/build_dashboard.py` regenerates `app-data.js` and mirrors `app.html`
into `index.html` on every run. The per-quarter static `{slug}.html` reports
still build and remain reachable directly (English only).

**Branding.** The SPA follows the gategroup brand guide: light theme, colour
tokens in `:root` of `app.html` (primary `#000064`, secondary `#0078C8` /
`#36424A` / `#A99667`, complementary `#8CDCDC`), navy top bar and landing hero,
Calibri-compatible font stack (gategroup Effra is not bundled; Carlito is loaded
as the web fallback). Category colours live in `CATEGORY_COLORS` in
`build_app_data.py`. The logo must come from the supplied files, never a retyped
wordmark. Logo files are in `public/reports/brand/` (cropped from the brand-guide
screenshot; replace with the official SVG/PNG when available). The static
`{slug}.html` reports use the same palette via the Tailwind token overrides in
`build_html.py` and the shell in `build_dashboard.py`.

**Languages.** The SPA is multilingual — English, German, French, Italian,
Spanish, Polish, Dutch, Portuguese and Romanian — via the language picker in
the header. See **Translations** below.

Slugs are `YYYY-MM` (the cover month of the Expana PDF) and map to a
**fiscal quarter** (the fiscal year starts in April): Apr–Jun → Q1,
Jul–Sep → Q2, Oct–Dec → Q3, Jan–Mar → Q4 (of the fiscal year that began
the previous April). e.g. `2026-04` = **Q1 2026**, `2026-07` = **Q2 2026**.
The mapping lives in `quarter_label()` in `build_app_data.py` and
`build_dashboard.py` — keep them in sync.

## Environment (Windows)

The pipeline was authored on Linux; on the user's Windows machine:

- Use the **`py`** launcher, not `python` (which hits a Store alias).
- Export **`$env:PYTHONUTF8 = "1"`** before every run — scripts print and
  write non-cp1252 chars (`·`, `✓`, `→`) and crash without UTF-8 mode.
- **`pdftotext`** (Poppler) is required by `extract.py`:
  `winget install --id oschwartz10612.Poppler`, then add its
  `...\poppler-*\Library\bin` to `$env:PATH`.

## Source of truth — read this first

**Never edit `public/reports/*.html` by hand for content changes.**
Those files are generated. Edit the source, then regenerate:

| Want to change…                              | Edit…                                            |
| -------------------------------------------- | ------------------------------------------------ |
| Trend Analysis, highlights, period dates     | `data/{slug}/meta.json`                          |
| A commodity's category / MoM / YoY           | `data/{slug}/commodities.json`                   |
| Remove a commodity (and its category card)   | delete row in `data/{slug}/commodities.json` — search count and category cards auto-update |
| Commodity commentary / paragraph             | `data/{slug}/commentary.json`                    |
| Forecast curves                              | `data/{slug}/forecast.json`                      |
| Germany sub-categories / drilldowns          | `data/{slug}/destatis.json` (built from the Destatis zip in `raw/`) |
| Indirect inflation (energy / freight / labour / packaging inputs) | `data/{slug}/indirect.json` |
| Headlines: KPIs, chart subtitles, table headers, column lists, drilldown layout | `scripts/build_html.py` |
| SPA layout / interactions / branding         | `public/reports/app.html` (then `build_dashboard.py` to mirror into index) |
| What data the SPA shows (KPIs, categories, movers, Germany) | `scripts/build_app_data.py` |
| Any UI wording, or adding a language         | `data/i18n.json`                                 |
| Translated highlights / commentary for one quarter | `data/{slug}/i18n/{lang}.json`             |
| Which quarters appear in the menu            | `data/manifest.json`                             |

Then regenerate:

```powershell
py scripts/build_html.py {slug}    # -> public/reports/{slug}.html + {slug}-germany.html
py scripts/build_dashboard.py      # -> rebuilds index.html menu + injects switchers
```

`index.html` is **not** a copy of a report — `build_dashboard.py` generates
it fresh as the quarter-picker menu from `manifest.json`. Always run
`build_dashboard.py` after `build_html.py` so the menu and in-report
switcher stay in sync.

```
  forecast.json      # daily forward curves (12 commodities)
  hicp_index.json    # current HICP series (Eurostat teicp010)
  germany.json       # Eurostat headline + prc_hicp_midx subcategories (required for Germany section)
  destatis.json      # Destatis 61111-0004 — preferred source for German drilldowns
  indirect.json      # optional: indirect-inflation pillars (energy/freight/labour/packaging inputs)
  i18n/{lang}.json   # optional: translated trend_analysis / highlights / commentary
  raw/               # original PDF / xlsx / Destatis zip — keep these
data/i18n.json       # translation catalogue for the SPA (all languages)
scripts/
  fetch_hicp.py      # Eurostat HICP → hicp_index.json
  fetch_destatis.py  # Destatis 61111-0004 zip → destatis.json
  fetch_germany.py   # Eurostat → germany.json (DE + EU27 headline + drilldowns)
  fetch_world_bank.py# WB pinksheet fetcher — nothing consumes its output today
  extract.py         # PDF + xlsx → commodities/commentary/forecast.json  (needs pdftotext)
  build_html.py      # JSON → public/reports/{slug}.html (+ {slug}-germany.html)
  build_app_data.py  # all quarters' JSON + i18n.json → public/reports/app-data.js
  build_dashboard.py # runs build_app_data, mirrors app.html→index.html, injects switchers
public/reports/
  app.html           # redesigned category-first SPA (source of the landing)
  app-data.js        # generated SPA data blob (window.CD_APP)

  {slug}.html        # generated static report, one per quarter (still reachable)
  {slug}-germany.html# generated, standalone Germany page
```

## Translations

`data/i18n.json` is the single source for every word the SPA renders. It is
authored **key-first** (all nine languages of one string side by side) and
`build_app_data.py` pivots it into per-language dictionaries inside
`app-data.js`. The build prints a warning listing anything that would fall
back to English, so a missing translation is never silent.

Rules that keep this working:

- **`build_app_data.py` must never emit a finished English sentence.** Labels
  go out as a translation key plus parameters (`{"k": "kpi.topHike", …}`);
  numbers, percentages and `"Jun 2026"` months go out raw and are formatted
  client-side against the active locale (decimal comma, `1,5 %`, `Juni 2026`).
- **Each language owns its own sentence shape.** Placeholders like
  `{notcomp}` exist so a language can put the negation where its grammar
  wants it — don't try to assemble sentences from fragments in JS.
- **Commodity names are translated** via the `commodities` section — keyed by
  the exact English name in `commodities.json` (minus the trailing `*`). The
  English name stays the row's identity (`data-open=`, `rep.rows` lookups);
  only the displayed text changes. A new quarter that introduces a new
  commodity still renders — it falls back to English — and the build prints
  the missing names, so add them when that warning appears. Kept untranslated
  on purpose: polymer acronyms (HDPE, LDPE, PET, PP), board grades (FBB, SBB,
  GC2, GT2, Kraftliner, Testliner), exchange names (ICE, LME, CBOT, CME,
  Euronext), varietals (Cheddar, Gouda, Arabica, Robusta), and the `US` / `UK`
  market tags — `EU` does become `UE` where that is the local abbreviation.
- **Analyst-written prose is not in the catalogue.** Quarter highlights and
  market commentary stay in the language they were written in. Drop a
  `data/{slug}/i18n/{lang}.json` with `trend_analysis`, `highlights` and/or
  `commentary` keys to override them per quarter; without it the SPA shows
  the English source plus a "written in English" note.
- Language choice comes from `?lang=xx`, then `localStorage`, then the
  browser's `Accept-Language`. The picker writes `?lang=` back into the URL so
  links are shareable.

Adding a language: add it to `languages` in `data/i18n.json`, fill in every
string, re-run `build_dashboard.py`, and check the build reports no fallbacks.

The static `{slug}.html` reports from `build_html.py` are **English only** —
they have their own layout code and were not part of the i18n work.

## Indirect inflation section

`data/{slug}/indirect.json` drives the SPA's **indirect inflation** screen
(`#/q/{slug}/indirect`): the cost pressure that reaches a delivered price
without appearing in the commodity quote — **energy**, **freight & logistics**,
**labour** and **packaging inputs** (pulp, recovered paper, feedstocks), plus a
macro backdrop and procurement actions. It is hand-authored from the Expana
monthly *Energy / Freight & Labor*, *Energy*, *Paper*, *Plastics* and *Weekly
Industrial & Macroeconomic* insight PDFs, archived alongside it in
`data/{slug}/raw/indirect-*.pdf`.

**It is kept separate from the direct commodity view on purpose.** The quarter
report screen carries no indirect content at all; indirect inflation has its own
landing section (`Indirect cost pressure`, between the quarter cards and the
regional deep-dive), its own route and its own screen — the same separation the
Germany deep-dive uses. Don't add a teaser or a summary panel back into the
quarter report: a freight index sitting next to commodity rows reads as if it
were a commodity price. The only ties between the two are the topbar
`Quarter report` link and the packaging `crosslink`.

The file is **optional**. A quarter without one renders no indirect section
anywhere — no landing section, no card — and the route falls back to a "no data"
message. Nothing else changes, so old quarters are safe.

Things to keep right when writing a new quarter's file:

- **Every driver carries its own `asOf`.** These series publish on different
  lags (ocean freight is same-month, EU labour costs are a quarter behind), so
  the section deliberately shows the latest print per series rather than forcing
  one common month. Don't backfill a stale figure to make the months match.
- **`basis` is `"mom"` or `"qoq"`.** EU labour-cost series from Eurostat are
  quarterly and not seasonally adjusted; they render with a `QoQ` marker so the
  Q4→Q1 bonus effect isn't misread as wage costs easing.
- **Don't repeat the commodity table.** Finished packaging (resins, board) is
  already in the `Packaging` category of `commodities.json`. The `inputs` pillar
  carries only what sits upstream of it; `crosslink` links the two.
- **Driver names, regions and macro labels go through `phrases`** in
  `data/i18n.json` — they are translated like commodity names. Analyst prose
  (`commentary`, `summary.headline`, `actions`) stays in its source language and
  the screen shows the "written in English" note once at the bottom.
- Pillar baskets (`netYoY`), the net pressure figure and the KPIs are all
  computed in `build_indirect()` — the JSON holds only raw values.

## Germany section data source

**Germany drilldowns come from Destatis Genesis Online table 61111-0004**
(base 2020 = 100), shipped as a CSV inside a zip in
`data/{slug}/raw/61111-0004_en*.zip`. `fetch_destatis.py` extracts the
zip into `data/{slug}/destatis.json`.

**But the Germany *section* only renders if `germany.json` exists.**
`build_html.py` gates the whole Germany page on the Eurostat headline in
`germany.json` (from `fetch_germany.py`); Destatis then overrides the DE
headline (CP01) and fills the drilldown panels. If you build a quarter
with only the Destatis zip and no `germany.json`, the report ships with no
Germany page. Always run `fetch_germany.py`; if Eurostat is firewalled,
copy the previous quarter's `germany.json` as a fallback.

**Annual-baseline view.** `data/{slug}/cpi_baselines.json` feeds the Germany
page's *Annual baselines* tab (159 Destatis CPI series: 2023/24/25 annual
averages vs the 2026 YTD average). It is extracted from the index-tracker
workbook with `py scripts/extract_cpi_baselines.py {slug} tracker.xlsx` (needs
openpyxl). Only public Destatis figures are read - never the workbook's
settlement-index parents, procurement mappings or thresholds - and the workbook
itself is not committed (public repo / public site).

**Germany price series on the indirect screen.** `data/indirect_de.json` (built by
`scripts/fetch_indirect_de.py --api`, not per quarter) feeds the *Germany* area of
`#/q/{slug}/indirect/germany`: electricity, gas, fuel, cardboard boxes, PPE &
plastic and logistics. Producer prices come from Destatis 61241-0006 (monthly,
GP2019 codes), logistics services from 61311-0006 (quarterly, CPA codes) and the
consumer-price items from the 61111-0004 pull already in `destatis.json`. The
series list lives in `SERIES` at the top of the script. The producer-price table
is too big for a synchronous download beyond 2025 onward, so those series start in
Jan 2025. The monthly workflow refreshes this file too.

**Other markets on the indirect screen.** `data/indirect_countries.json` (built by
`scripts/fetch_indirect_countries.py`, public APIs, no token) adds UK, Ireland,
Denmark, Sweden, Norway, Netherlands and Italy next to Germany at
`#/q/{slug}/indirect/countries/{CC}`. Eurostat supplies IE DK SE NO NL IT
(`prc_hicp_minr` consumer prices, `sts_inppd_m` producer prices, `sts_sepp_q`
services) and the ONS time-series API supplies the UK (CPI MM23, PPI, SPPI;
the ONS API rejects requests without a User-Agent). Eurostat does not publish
every NACE class per country, so the script falls back to the next wider class
(C1721 -> C172 -> C17, C222 -> C22, D351/D352 -> D35) and the series label says
which one was used. Eurostat road-freight services (H494) are not published for
these countries, so logistics uses H52 (warehousing & transport support).

**Labour, business energy and FX (same file).** `fetch_indirect_countries.py` also pulls:
hourly labour cost index (Eurostat `lc_lci_r2_q`, accommodation & food with
fallbacks; UK uses ONS average weekly earnings from the EMP dataset, whose URL
path differs from the price datasets), business-user electricity and gas prices
(Eurostat `nrg_pc_205` band 500-1,999 MWh and `nrg_pc_203` band 1,000-9,999 GJ,
excl. VAT, half-yearly, EUR/kWh; no UK equivalent) and monthly ECB exchange rates
for GBP, DKK, SEK and NOK. Germany's extra series come from the same file and are
merged into the Destatis ones in the client. FX series are shown without
risk/opportunity colouring - a weaker local currency is not "bad" in itself.

**Automatic refresh.** `.github/workflows/refresh-destatis.yml` ("Refresh data
(automatic)") runs by itself every Monday 06:17 UTC and on demand from the Actions
tab. It downloads Destatis 61111-0004 via the Genesis API (repository secret
`GENESIS_TOKEN`), rebuilds the German series and the country series (Eurostat, ONS,
ECB - no token), refreshes the newest quarter in `manifest.json`, commits to `main`
only if a number changed, and starts the Pages deploy. A failed run opens or
updates an issue titled "Automatic data refresh failed". Not automatic by nature:
the Expana overview PDF, the Mintec forecast and the Expana indirect-inflation
PDFs (licensed files someone has to drop in `input/`). Locally:
`GENESIS_TOKEN=... py scripts/fetch_destatis.py {slug} --api`.

Each drilldown panel includes the parent COICOP series (e.g. CP0122) as
the first row + a white dashed line, alongside its 5-digit children
(CP01221, CP01222, …).

## Food CPI dashboard

`data/food_cpi.json` (built by `scripts/fetch_food_cpi.py`, public APIs, no token, not per
quarter) drives the SPA's **Food CPI** screens: `#/food` (markets x product-group
heat table with YoY/MoM toggle and month picker, key-product rows, multi-market trend)
and `#/food/{CC}[/{code}]` (all food series of one market: category rail, chart,
indented product table, search, history modal). Markets: UK, IE, DK, SE, NO, NL, IT,
DE, FR, ES, PL, PT, RO, EU27, euro area. Sources: Eurostat `prc_hicp_minr`
(ECOICOP v2, 2025 = 100, every `CP01*` code, 101 per market, names also fetched in
de/fr) and ONS MM23 (UK CPI, 2015 = 100, 63 series; the CDID list `UK` is hard-coded in
the fetch script, and `F_UKMAP` in `app.html` maps EU classes to them for the comparison
table). Compare changes, never index levels, across markets (different bases).

**Germany is merged in:** `#/food/DE` renders the existing Germany deep-dive (Destatis
national CPI, 60 items, categories, annual baselines) inside the food dashboard; the
comparison table uses the Eurostat HICP for Germany so it lines up with the others.
`#/q/{slug}/germany` still works. Product names come from the source taxonomy (English,
with de/fr from Eurostat) - not in `i18n.json`; UI strings are `food.*` keys. The weekly
refresh workflow runs the fetch and includes the file in its change check.

## Common edit recipes

### Remove a category / commodity from the dashboard
1. Delete the rows from `data/{slug}/commodities.json`.
2. (Optional) Delete the matching entries from `data/{slug}/commentary.json`.
3. Re-run `py scripts/build_html.py {slug}`, then `py scripts/build_dashboard.py`.
   Search count, category cards, and dropdown options auto-update from the
   new commodity list — no HTML edits needed.

### Tweak Trend Analysis or highlights wording
Edit `data/{slug}/meta.json` → `trend_analysis` or `highlights[].body`,
then regenerate.

### Rename a column header / chart subtitle / KPI caption
Edit `scripts/build_html.py`. Search the literal string and change it in
one place. Regenerate.

### Change the landing-menu branding or card layout
Edit `scripts/build_dashboard.py` (`build_index` for the menu page,
`shell_html` for the in-report header/switcher), then re-run it.

## Build / deploy flow

1. Edits → `data/{slug}/*.json` and/or `scripts/*.py`.
2. `py scripts/build_html.py {slug}` regenerates the report HTML.
3. `py scripts/build_dashboard.py` regenerates `index.html` + switchers.
4. Commit the changed `data/{slug}`, the regenerated `.html`s,
   `public/reports/index.html`, and `data/manifest.json`.
5. **Push to `main`** — `.github/workflows/pages.yml` deploys
   `public/reports/` to GitHub Pages on every push to `main` that touches
   that directory. Other branches do **not** deploy.

> **Always finish the job by pushing.** Any change to this repo is only
> real once it is on `main` — work that stops at a local commit or a
> feature branch leaves the live dashboard on the old build, which reads
> as "nothing happened". So after every update: rebuild, commit, merge to
> `main`, push, and confirm the Pages workflow went green before saying
> it is done. Don't stop to ask whether to deploy; that is the standing
> instruction. (Still say what you pushed, and still ask first for
> genuinely destructive things — history rewrites, force pushes, deleting
> source data.)

Confirm the deploy with the GitHub Actions API (workflow
`pages.yml` → the `build` and `deploy` jobs both `success`). Note that
`*.github.io` may be blocked by the sandbox proxy, so a failed fetch of
the live URL is not evidence that the deploy failed.

## Gotchas observed in real sessions

- **Windows encoding** — without `$env:PYTHONUTF8="1"`, `build_html.py`
  and the fetch scripts crash with `UnicodeEncodeError` on `·` / `✓`.
  (build_html now writes UTF-8 explicitly; the fetch scripts still print
  Unicode to the console, so keep the env var set.)
- **`pdftotext` missing** — `extract.py` shells out to Poppler's
  `pdftotext -layout`. Install Poppler and put it on PATH.
- **No Germany section** — you built with the Destatis zip but no
  `germany.json`. Run `fetch_germany.py`.
- **Germany content is JSON-encoded inside the main HTML.**
  `<script id="cd-germany-payload" type="application/json">…</script>`
  holds an escaped HTML string. To verify changes there, parse the JSON
  first (`json.loads(payload)`) — direct grep often misses matches.
- **Eurostat is firewalled in some environments.** `fetch_germany.py` and
  `fetch_hicp.py` may hit 403s. Use cached JSON or the Destatis zip.
- **`teicp010` ≠ CP01.** Eurostat's short-term `teicp010` is *labeled*
  "HICP - food" but doesn't share a base year with Destatis CP01; they
  can't share a Y axis without rebasing. The dashboard uses Destatis only
  for German values to avoid this.
- **Carried-over forecast.** If `forecast.xlsx` was reused from a prior
  quarter, the forward curves are stale — refresh and rebuild when the new
  Mintec export arrives.
